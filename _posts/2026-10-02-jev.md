## What is Jev?

Jev is a new model released by [TypeSafe AI](https://typesafe.ai/). The company reports up to **200x faster inference** and **400x lower cost** than comparable LLMs on classification tasks.

It's built to make fast decisions rather than generate text. Feed it messy data — an email, a support ticket — and it returns structured answers: scores, probabilities, true/false choices. No paragraphs, no chat, just typed outputs your software can act on.

**Best uses:** sorting emails, flagging spam, routing customer support requests.

## System One Models

Jev is TypeSafe's first **System One Model** — a new class of AI built natively for machines, not humans.

| Concept | Description |
|---------|-------------|
| **System One Models** | AI models trained for structured decisions from the start, returning typed answers with calibrated probabilities |
| **RLCD** | Reinforcement Learning for Calibrated Decisions — the new training method behind Jev |
| **Typed outputs** | Answers come with probabilities and confidence scores that software can act on directly |

### How it differs from standard LLMs

Jev replaces sequential token generation with **parallel computation**, answering multiple structured questions in a single request. This makes it fast and cheap enough to bring intelligence to everyday software decisions — including ones that never justified the cost of an LLM before.

> The jump from sequential to parallel is similar to the leap the transformer made over RNNs — the breakthrough underlying today's AI revolution.

### What Jev is designed for

1. Classifying content
2. Routing requests
3. Scoring responses
4. Evaluating information

These decisions can be combined in code to form larger workflows.

### What Jev is NOT designed for

Tasks requiring extended reasoning — complex mathematics, chess-like planning — are better suited to large reasoning models.

## Stage-by-Stage ADLC Execution

1. **Plan & Design:** Originators brainstorm with Claude to codify requirements into structured markdown files before any implementation starts.
2. **Build:** Agents operate across parallel worktree sessions using build-time hooks, repository context, and specialized skills.
3. **Test:** Continuous verification loops require automated test-driven development (TDD), linting, and building to pass successfully ("green") before an agent marks a task complete.
4. **Deploy:** Pull requests undergo automated checks, permission hooks, and sandboxed, non-interactive CI/CD executions before hitting human approval gates.
5. **Maintain:** Headless monitoring triggers handle alert triage, root-cause production log analysis, security scans, and automated patch drafting.
