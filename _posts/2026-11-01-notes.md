## OpenLineage Producer and Consumer 

1. An OpenLineage Producer is a system, engine, or application  
1. generates and emits OpenLineage Events (START, RUNNING, COMPLETE, FAIL) (on what? Kafka?)
2. describing how data is processed during its runtime.
3. Definition: Any tool that instruments data transformation and sends structured JSON/protobuf events to an OpenLineage consumer (such as Marquez, DataHub, OpenMetadata, or Amazon DataZone).
4. The producer Field: Every OpenLineage event requires a producer URI field — a unique identifier or link pointing to the source code, version, or client library that generated the metadata (e.g., https://github.com/OpenLineage/OpenLineage/blob/v1-0-0/client).
5. Core Concepts Emitted: Producers track three primary entities plus metadata extensions:
6. Job: A persistent definition of a data process (e.g., a Spark application, Airflow DAG task, or dbt model).
7. Run: A specific execution instance of a job associated with a unique runId.
8. Dataset: The input and output data sources (tables, files, topics) touched during the run.
9. Facets: Optional modular metadata modules (like schemas, SQL queries, column-level lineage, or error stats).
